## 1. コンセプトと設計原則

比較サイトで疲れるのは、選択肢が多すぎて**決める作業がユーザーに残る**から。キメタビはその作業を引き受け、1つのプランを実行できる状態まで仕上げる。

| # | 原則 | 具体的なルール |
|---|---|---|
| P1 | 出すのは1案だけ | 候補リスト・比較表は出さない。 |
| P2 | 別案は差分で見せる | 「+¥6,000で駅徒歩2分」「−40分で乗換なし」のように、今の案との違いだけを示す。一度に見せる別案は最大2つ。 |
| P3 | 選んだ理由を1行で添える | 宿・店・移動の各ブロックに「なぜこれか」を必ず付ける。 |
| P4 | 成立することを保証する | 営業時間・定休日・乗換・チェックイン時刻を照合し、問題のある案は出さない。 |
| P5 | 予約まで一気に進める | 確定したら、そのまま予約の手順へ進む。 |
| P6 | 中立性 | **アフィリエイト手数料の高さをプラン選定に使わない。** PR枠はプラン本体の外に「PR」と明記して置く。 |

トーン：「迷ったらこれ」と言い切る、プロのコンシェルジュの口調。

## 5. 旅のしおり

中学・高校の修学旅行で作ったしおりを、確定したプランから自動で作る。**課金の動機と口コミ拡散の両方を担う目玉機能。**

### 5.1 構成（ページ順）

| # | ページ | 内容 |
|---|---|---|
| 1 | 表紙 | 旅のタイトル、日付、行き先、メンバー名、テーマイラスト |
| 2 | 旅のめあて・メンバー | 旅の一言、メンバーと役割（例：写真係、会計係）、旅のルール |
| 3 | 日程表（日ごと） | 時間割、集合時刻・場所、移動（列車名・座席）、各スポットの地図QR |
| 4 | 食べるものリスト | 店名、頼むべき一品、予約の有無 |
| 5 | 宿のページ | 宿名、住所、電話、チェックイン／アウト、夕食・朝食時刻 |
| 6 | 持ち物チェックリスト | 天気連動、チェックボックス付き |
| 7 | お金のページ | 総額内訳、割り勘メモ欄 |
| 8 | 緊急連絡先 | 宿、交通機関、最寄りの病院 |
| 9 | 思い出ページ | 感想欄、スタンプ・写真貼り付け欄 |

### 5.2 機能

| ID | 機能 | 優先度 | 無料 | 有料 |
|---|---|---|---|---|
| F-50 | デジタル版（共有リンク） | MVP | ✓ | ✓ |
| F-51 | 印刷用PDF（A4で出力、二つ折りでA5冊子） | MVP | ✓（ロゴ入り） | ✓（ロゴなし） |
| F-52 | デザインテーマ | MVP | 標準のみ | 修学旅行風／レトロ／ポップ／和風／記念日 |
| F-53 | メンバー名・役割・旅のルール編集 | MVP | ✓ | ✓ |
| F-54 | 思い出しおり（写真を入れてアルバム化） | v1.x | — | 年額プランのみ |

### 5.3 デザイン方針

- 紙で見て楽しい：罫線、見出しの帯、手書き風の余白、スタンプ枠。
- 情報は正確に：時刻・列車名・住所はプランのデータから自動で差し込み、手入力させない。
- 印刷前提：白地、A5の余白（外側12mm以上）、QRは15mm角以上。
- プランを変更したら、しおりも自動で更新（最終更新日時を表紙に表示）。

## 6. プラン生成ロジック

### 6.1 処理の流れ

```
条件（入力＋デフォルト）
  → ① 行き先の決定（おまかせ時：季節・予算・移動時間・旅の軸でスコアリング）
  → ② 移動の骨組み（往復の便・列車を確定）
  → ③ 宿の決定（予算配分、立地、旅の軸との一致、空室）
  → ④ 時間割の組み立て（スポット・食事を配置、移動時間を挿入）
  → ⑤ 成立チェック（NGなら④に戻る）
  → ⑥ 理由文・旅のタイトル生成
  → プラン出力
```

- ①〜④の候補探索は外部APIの実データを使い、LLMは**選定の説明・時間割の組み立て・理由文**に使う。
- 事実（営業時間・時刻表・料金）は必ずAPIのデータを正とし、LLMの出力で上書きしない。

### 6.2 予算配分の初期値

| 項目 | 配分 |
|---|---|
| 交通 | 実費（先に確定） |
| 宿 | 残りの55% |
| 食事 | 残りの30% |
| 入場料・体験 | 残りの10% |
| 予備費 | 残りの5% |

旅の軸で補正する（例：「食」なら食事+10%、宿−10%）。

### 6.3 成立チェック

| チェック | 内容 |
|---|---|
| 営業時間 | 滞在時間帯が営業時間内か |
| 定休日 | 訪問日が定休日でないか（臨時休業はデータがあれば反映） |
| ラストオーダー | 到着時刻がLOより30分以上前か |
| 移動時間 | 乗換時間の余裕（新幹線は10分以上、在来線は5分以上） |
| 宿の時刻 | チェックイン開始後に到着、夕食時刻に間に合うか |
| 最終便 | 帰りの便に余裕があるか（最終便は避ける） |
| NG条件 | 起床時刻、乗換回数、徒歩距離、食事制限 |
| 予算 | 総額が予算内か |

### 6.4 部分調整の再計算

- 差し替え対象だけ再探索し、前後の時間割を再調整する。
- 表示するのは差分だけ：金額差、時間差、理由の違い。
- 差し替えで成立しなくなる場合は、その案を出さない。

## 8. 外部データソースと予約連携

| 用途 | 候補 | 備考 |
|---|---|---|
| 宿泊（在庫・料金） | 楽天トラベルAPI | 空室検索・料金・予約ディープリンク |
| 宿泊（在庫・料金） | じゃらん（Webサービス／アフィリエイト） | 提供条件・現行APIの可否は要確認 |
| 鉄道・経路 | 駅すぱあと API または NAVITIME API | 時刻表・運賃・乗換。商用利用は有償契約 |
| 飲食店・スポット | Google Places API | 営業時間、定休日、評価、位置 |
| 地図・QR | Google Maps URL | しおりのQRはMaps URLを埋め込む |
| 天気 | 気象API（要選定） | 雨の日版、持ち物リスト |
| 生成 | LLM API | 時間割の組み立て、理由文、タイトル |

**予約連携の方針**

1. MVP：ディープリンク（アフィリエイト経由）で各サイトに遷移し、予約はユーザーが行う。
2. v1.x：予約完了メールの転送や手動チェックで予約状況を反映。
3. 将来：API連携による予約代行。

**注意**

- 各APIの利用規約（キャッシュ期間、表示義務、商用利用条件）を契約前に確認する。
- 料金や空室はリアルタイムで変わるため、プラン画面に「◯分前時点の情報」と表示する。

## 9. 料金体系と収益モデル

### 9.1 前提

国内旅行は**年2〜4回**程度で、月額サブスク単体では「旅行前に加入、旅行後に解約」になりやすい。そこで以下を組み合わせる。

| 収益源 | 位置づけ | 目安 |
|---|---|---|
| ① 予約アフィリエイト | 土台（無料ユーザーからも） | 料率は概ね1〜数%（ASPごとに要確認） |
| ② 旅パス（1旅行の買い切り） | 課金の入口 | ¥680 |
| ③ 年額プラン | 主力 | ¥4,800/年 |
| ④ 製本しおり | 物販で単価上乗せ | ¥1,500〜¥3,000/冊 |
| ⑤ 法人・幹事向け | 将来 | 別料金 |

### 9.2 無料と有料の線引き

無料でも**完成した1プランは必ず体験できる**ようにする。

| 機能 | 無料 | 旅パス | 年額 |
|---|---|---|---|
| 1プランの生成 | 月1回 | その旅で使い放題 | 無制限 |
| 部分調整 | 3回まで | 無制限 | 無制限 |
| 成立チェック・予約チェックリスト | ✓ | ✓ | ✓ |
| 旅のしおり | 標準デザイン（ロゴ入り） | 全テーマ・ロゴなし | 全テーマ・ロゴなし |
| 当日モード（再計画） | — | ✓ | ✓ |
| 拒否権モード | 閲覧のみ | ✓ | ✓ |
| 価格監視・空き通知 | — | ✓ | ✓ |
| 好みの学習 | — | — | ✓ |
| 思い出しおり | — | — | ✓ |
| 家族共有（最大5人） | — | — | ✓ |
| 製本しおり | 通常価格 | 通常価格 | 10%割引 |

見せ方：「旅パス¥680／年額¥4,800（旅パス約7回分）」。

### 9.3 試算（1,000旅行あたり、仮定値）

| 項目 | 仮定 | 売上 |
|---|---|---|
| 予約アフィリエイト | 予約率40%、1件¥800 | ¥320,000 |
| 旅パス | 課金率8%、¥680 | ¥54,400 |
| 年額プラン | 加入率3%、¥4,800 | ¥144,000 |
| 製本しおり | 購入率2%、粗利¥800 | ¥16,000 |
| **合計** | | **約¥534,000（1旅行あたり約¥530）** |

- コスト：LLM・外部APIの費用は部分調整の回数に比例する。無料ユーザーの回数制限はコスト対策も兼ねる。

## 10. KPI

| KPI | 定義 | 意味 |
|---|---|---|
| **確定率**（北極星） | 生成したプランのうち「このプランで決める」が押された割合 | 決め切れたか |
| 予約遷移率 | 確定プランのうち、1件以上予約に進んだ割合 | 収益に直結 |
| 部分調整回数 | 確定までの平均調整回数 | 少ないほど初回の案が良い |
| 有料転換率 | 無料 → 旅パス／年額 | |
| 年額継続率 | 年額プランの更新率 | |
| しおり共有率 | しおりの共有リンクが開かれた割合 | 口コミ・拡散 |
